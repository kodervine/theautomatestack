# The Automate Stack: site, blog and freebies

Plain static website for theautomatestack.com, plus a small blog generator and a freebie form that saves leads to Notion.

## How the repo is organised

```
public/              the live site. Only this folder is published (see vercel.json)
  index.html           home (generated from templates/pages/home.html)
  freebies/            free resources + the signup form (generated)
  starter-kit/         Starter Kit page (generated)
  dm-automation/       DM automation page + consultation (hand-written)
  services/            consulting and business automation (hand-written)
  blueprint/           Blueprint sales page (hand-written)
  blog/                generated by npm run build
  assets/css, img, video
api/lead.js          the form handler (runs on Vercel, saves to Notion)
config/              site.json (links, names), freebies.json (the freebies list)
content/posts/       blog posts in markdown
templates/           layouts and partials (header, footer, CTA...)
scripts/             build, sync, draft, export, check
archive/             old files kept for reference (not published)
```

Nothing outside `public/` is published, so drafts, scripts and config stay private.

## One-time setup

1. `npm install`
2. Copy `.env.example` to `.env` and fill it in. `.env` is private and ignored by git.

## Everyday commands

| Command | What it does |
|---|---|
| `npm run build` | Rebuilds the generated pages, blog, sitemap, robots.txt and llms.txt into `public/` |
| `npm run dev` | Local preview at http://localhost:3000, rebuilds on save. The freebie form works here too. Add `-- --drafts` to see drafts |
| `npm run check` | Checks the pages: structure, SEO tags, JSON-LD, sitemap, RSS and broken links |
| `npm run new -- "post title"` | Starts a new blog post |
| `npm run sync` | Pulls Ready posts from Notion |
| `npm run draft -- "slug"` | Drafts a post in your voice into Notion (needs `GEMINI_API_KEY`) |
| `npm run mark-published` | After you deploy, sets Status = Published in Notion |
| `npm run medium` | Makes Medium export files in `dist/medium/` |

Always run `npm run build` and `npm run check` before you push. The build output in `public/` is committed.

## Change links once

All links live in `config/site.json`: Instagram, TikTok, YouTube, Starter Kit, Blueprint, the two consultations, your Selar store, and your name and bio. `process_consultation_url` currently points to your Selar store. Change it when you create the end-to-end consultation listing.

Brand colors and fonts are in `public/assets/css/brand.css`.

## Publishing (GitHub to Vercel)

Push to GitHub and Vercel publishes, if the repo is connected to a Vercel project. `vercel.json` tells Vercel to serve `public/`, skip install and build (the site is pre-built), and redirect the old `/home/` page to `/services/`.

Tip: push to a branch first. Vercel gives you a preview link so you can check before it goes live on `main`.

## Freebies and the Notion lead form

Freebies are listed in `config/freebies.json`. To add one, copy the first entry, give it a new `id`, `title`, `description` and `download_url` (where the file lives, for example a Selar free product), then run `npm run build`. It appears on `/freebies/` with its own form.

When someone submits the form, `api/lead.js` adds a row to your Notion **Leads** database: Name, Email, Status = New, Source, and a note saying which freebie and that they consented. The same email is not added twice. Then they are sent straight to the download link (the Selar page). No email is sent by this site. Selar delivers the free product itself.

**Set this up once in Vercel** (Project > Settings > Environment Variables):

1. In Notion, go to https://www.notion.so/profile/integrations and create a new integration, for example "Website forms". Copy its token.
2. Open the **Leads** database in Notion, click `...` > Connections, and add that integration. Do not give it access to anything else.
3. In Vercel, add `NOTION_LEADS_TOKEN` with that token. Redeploy.

The Leads database now has an **Email** column, which the form fills. If a save ever fails the visitor still gets their download, and the error shows in Vercel's function logs.

## The blog

Add a post by hand with `npm run new -- "title"`, or sync from Notion. Status decides what happens: `draft` is never built, `ready` and `published` are built. A post that still contains `[CHINENYE: ...]` will not build.

Notion sync, drafting and the Medium export work as before. Medium has no publishing API, so `npm run medium` makes files and a checklist: publish on your site first, import the live URL into Medium, then paste the Medium URL back into Notion.

The Blog link and RSS tag only appear on the site once at least one post is published.
